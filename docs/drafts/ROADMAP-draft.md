# Як розвивати навичку далі

Базова версія відповідає на запити про одну тему в кількох мовах на кошику до кількох десятків статей. Нижче — наступні кроки в порядку користі, кожен із критерієм, коли він потрібен.

## 1. Надійність на поточному масштабі

- **Регресійні evals у CI.** Прогін `evals/run_agent.py` на дешевій моделі за всіма сценаріями `evals/scenarios.yaml` після кожної зміни SKILL.md чи CLI; поріг — жодного нового провалу критичних перевірок.
- **Калібрування порогів** (`anomaly_k`, `spike_k`, правила довіри) на більшій кількості тем: зараз відомі межові хибні аномалії влітку в роки різкого спаду.

## 2. Автоматичний підбір кошика

Зараз кошик пропонує агент із власних знань, а код лише перевіряє. Наступний крок — команда `suggest`: кандидати з категорій Wikipedia, властивостей Wikidata (частина від, підклас, тема) і мета-списку «List of articles every Wikipedia should have», з ранжуванням за наявністю в усіх потрібних мовах. Це зменшує довільність вибору (відомий слабкий момент навіть після доведення baseline) і робить результат відтворюваним між агентами.

## 3. Складніші дослідження

- **Порівняння багатьох тем** (портфель курсів): одна специфікація з кількома target-кошиками, звіт — ранжування тем із довірою.
- **Сегменти аудиторії** через групи всередині кошика (навчальні статті vs статті про гравців, як у сценарії D) з окремими висновками.
- **Події та сезонність у звіті**: вирівнювання графіків під шкільний рік чи сезон, позначення відомих подій, щоб засновник бачив, коли запускати.
- **Інші джерела поруч із Wikipedia** як окремі навички з тим самим форматом метрик (пошукові тренди, магазини застосунків), щоб звіт показував кілька незалежних сигналів.

## 4. Більші обсяги даних

- **Дампи Wikimedia замість API**, коли статей тисячі: `pageview_complete` дає всі статті всіх мов за день одним файлом; обробка потоково, в той самий SQLite або DuckDB/Parquet.
- **Обмежений паралелізм** у межах правил Wikimedia (кілька одночасних запитів із контактом у User-Agent) замість строго послідовних.
- **Спільний кеш** між сесіями й користувачами команди (файл у спільній папці або невеликий сервіс), щоб повторні теми не завантажувались двічі.
- **Інкрементальне оновлення**: щомісячне дозавантаження лише нового місяця для збережених досліджень і повідомлення, якщо висновок змінився.

## 5. Упаковка

- Plugin для Claude Code з цією навичкою і, можливо, командами `/wiki-interest:report`, з `claude plugin eval` для регресійних перевірок.
- Публікація через репозиторій навичок для встановлення однією командою.
