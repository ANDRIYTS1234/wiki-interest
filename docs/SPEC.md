# SPEC: код навички wiki-interest

Цей документ — контракт коду навички. SKILL.md пишеться пізніше, навколо цього контракту. Обґрунтування кожної вимоги — у протоколах baseline-прогонів (`evals/baseline/`): там записано, де сильна модель без навички помилялася.

## 1. Принципи

1. Усе, що має одну правильну відповідь (запити до API, кеш, редиректи, метрики, перевірки стійкості, графіки, верстка), робить код. Агент лише формулює запит, погоджує склад кошика статей і пише текст висновків.
2. Жодних мовчазних замін і пропусків. Якщо статті немає, запит не вдався або даних бракує — це явний статус у виводі або помилка з ненульовим кодом виходу.
3. Кожне число у звіті походить із метрик. Текст агента не може містити чисел, яких немає в metrics.json.
4. Вивід зручний для слабкої моделі: stdout — компактний JSON (зазвичай до ~2 КБ), великі артефакти — у файли, шляхи до яких є у stdout.
5. Детермінованість: фіксований seed для bootstrap, однакові вхідні дані дають побайтово однаковий metrics.json.
6. Повторні й пов'язані запити не ходять в API вдруге: усе кешується локально, дозавантажуються лише відсутні діапазони.

## 2. Портативність

- Python ≥ 3.10. Жодних системних залежностей поза Python.
- Залежності лише з готовими wheel-пакетами для Windows, macOS, Linux: requests, pandas, numpy, matplotlib, reportlab. Без WeasyPrint, Cairo, Pango тощо.
- Основне встановлення — `uv` (pyproject.toml + uv.lock). Запасне — `requirements.txt`, згенерований із uv.lock, для `python -m venv` + `pip`.
- Кеш — стандартний модуль `sqlite3`, один файл. За замовчуванням `./.wiki-interest-cache/cache.sqlite` у поточній робочій папці; змінна `WIKI_INTEREST_CACHE` перевизначає шлях. Якщо запис неможливий — помилка з поясненням.
- Шрифт — DejaVu Sans із даних самого matplotlib (`matplotlib.get_data_path()`), зареєстрований і для matplotlib, і для reportlab. Системні шрифти не використовуються.
- На старті кожної команди stdout і stderr перемикаються на UTF-8 (`sys.stdout.reconfigure(encoding="utf-8")`).
- Усі шляхи через `pathlib`. Назви статей ніколи не передаються через shell-аргументи, лише через JSON-файли (апостроф у «Сузір'я» ламав bash у baseline).
- Мережа: код розрізняє «мережа або домен недоступні» (код виходу 3), «обмеження частоти вичерпано» (4), «даних неповно» (5) і повідомляє причину з підказкою.

## 4. Спільне для всіх команд

- Глобальні опції: `--cache-dir`, `--workdir` (куди писати артефакти, за замовчуванням `./wiki-interest-out/`).
- User-Agent: `wiki-interest/<версія> (<контакт>) python-requests/<версія>`. Контакт зі змінної `WIKI_INTEREST_CONTACT`; якщо її немає — URL проєкту з `[project.urls]` у pyproject.toml і попередження в stderr. Вигаданих контактів не підставляти.
- Успіх: stdout — `{"ok": true, ...}`, код 0. Помилка: `{"ok": false, "error": {"code": "...", "message": "...", "hint": "..."}}`, коди: 2 — невалідний вхід, 3 — мережа, 4 — rate limit, 5 — неповні дані, 1 — інше. Трасування лише в stderr.
- Логи прогресу — у stderr, stdout лише фінальний JSON.
- Кожен вихідний JSON містить `tool_version` і `data_as_of` (останній повний місяць даних).

## 5. HTTP-шар

- Один запит за раз за замовчуванням, мінімальний інтервал між запитами (0,25 с, налаштовується).
- 429 і 5xx: повтор з експоненційною паузою, з урахуванням `Retry-After`, до 6 спроб; далі — код 4 або 3.
- Відповідь, яка не є валідним JSON там, де очікується JSON, — це помилка, а не порожній результат.
- Мережеві помилки (DNS, з'єднання, проксі, відмова в доступі до домену) — код 3 з назвою домену.

## 6. Команда `resolve`

Мета: знайти тему в потрібних мовах так, щоб нічого не губилося мовчки.

Вхід: `--input resolve.json`:
```json
{"items": [{"query": "інтервальне голодування", "query_lang": "uk"}, {"qid": "Q1666254"}],
 "langs": ["pl", "cs"]}
```

Логіка:
1. Для `query` — `wbsearchentities` мовою `query_lang` (запасна — en). Якщо перший кандидат не очевидно єдиний, повернути до 5 кандидатів (`qid`, `label`, `description`) і `needs_choice: true`, нічого не обирати самостійно.
2. Для `qid` — `wbgetentities` зі sitelinks для кожної мови.
3. Для кожної знайденої статті через MediaWiki API: чи це сторінка неоднозначності (pageprops `disambiguation`), чи редирект, повний список редиректів на неї (`prop=redirects`, усі сторінки продовження), дата першої ревізії, довжина, історія перейменувань (журнал `move`) з датами — щоб завантажувати перегляди й під старими назвами.
4. Якщо статті в мові немає: `status: "missing"` і до 5 результатів повнотекстового пошуку в цій мові з поміткою `not_equivalent: true`. Замінник обирає агент разом із користувачем, код — ніколи.

Вихід (stdout і `resolve_result.json`): для кожного item і мови — `status` (`ok` | `missing` | `disambiguation` | `redirect_resolved`), `title`, `qid`, `created`, `length`, `redirects[]`, `former_titles[{title, moved_at}]`, `search_hits[]`. Плюс матриця покриття «item × мова».

Регресійні кейси з baseline (мають бути в тестах на фікстурах): uk «Марс» — неоднозначність; pl інтервальне голодування (Q1666254) — відсутня; es «Reglas del ajedrez» — редирект, справжня стаття «Leyes del ajedrez»; uk «Нейтронна зірка» → «Нейтронна зоря» (перейменування 2021).

## 7. Команда `fetch`

Вхід: `--spec analysis.json` (той самий файл, що для `analyze`, розділ 8).

Логіка:
1. Для кожної сторінки кошиків (плюс її редиректи й колишні назви з resolve) — денні перегляди від `2015-07-01` (або `history_start`) до останнього повного місяця:
   - `user`, all-access;
   - `automated`, all-access;
   - `user`, desktop (мобільні = all − desktop).
2. Агрегати кожного мовного розділу за ті самі дні для `user` і `automated`.
3. SQLite-таблиці: `pageviews(project, article, access, agent, day, views)`, `coverage(project, article, access, agent, start, end, fetched_at)`, `http_cache(url, body, fetched_at)` для MediaWiki/Wikidata з TTL 7 днів. Дні без запису в API = 0 лише в межах підтвердженого покриття.
4. Дозавантажувати лише відсутні діапазони.
5. Якщо хоч одна серія не завантажилась — код 5 зі списком. Прапорець `--allow-partial` дозволяє продовжити, але пише `missing_series[]`, які `analyze` перетворює на прапорці якості.

Вихід: `{"ok": true, "requests": N, "cache_hits": M, "series": K, "missing_series": [], "data_as_of": "YYYY-MM"}`.

## 8. Команда `analyze`

Вхід: `--spec analysis.json`:
```json
{
  "question": "Чи зростає інтерес до астрономії в uk.wikipedia?",
  "langs": ["uk"],
  "window": {"months": 12, "end": "latest"},
  "history_start": "2016-01",
  "baselines": [2019, 2021],
  "baskets": [
    {"id": "target", "role": "target", "label": "Астрономія",
     "items": [{"qid": "Q333"}, {"lang": "pl", "title": "Głodówka lecznicza", "proxy_for": "Q1666254"}]},
    {"id": "control", "role": "control", "label": "Інші природничі науки", "items": [{"qid": "Q413"}]}
  ]
}
```
Ролі кошиків: `target` (тема), `context` (суміжні теми), `control` (порівняльна група). Елемент — `qid` (назви з resolve) або явні `lang`+`title`, з необов'язковим `proxy_for`.

Метрики для кожного кошика × мова:
- **Вікно:** поточні N місяців проти тих самих місяців роком раніше (прибирає сезонність); абсолютна зміна і зміна частки в трафіку розділу (на 1 млн переглядів); медіана місяця.
- **Індекс кошика:** середнє геометричне відношень «поточне / попереднє» по статтях (статті з дуже малими обсягами — за порогом, налаштовується), bootstrap-інтервал 95% по статтях, 2000 перевибірок, фіксований seed.
- **Стійкість:** діапазон leave-one-out; без 3 найбільших статей; медіана відношень по статтях; альтернативні бази з `baselines`.
- **Разові сплески:** день понад k× (за замовчуванням 5) від ковзної 29-денної медіани і понад мінімальний абсолютний приріст; для кожного — дата, перегляди, частка automated, частка desktop проти звичайної; метрики вікна, перераховані без сплесків (сплеск замінюється медіаною).
- **Аномальні місяці:** частка місяця в річних переглядах проти типового сезонного профілю з історії; стрибки automated.
- **Довга історія:** річні нормовані значення, рік піку, поточне як % від піку; позначка, якщо стаття створена пізніше за `history_start`; база кошика — перший рік, коли існують усі статті.
- **Тренд:** Mann–Kendall і Theil–Sen на річних нормованих значеннях.
- **Порівняння мов:** відношення індексів кошиків з bootstrap-інтервалом по спільних QID.
- **Сезонність:** середня частка кожного місяця року.

Прапорці якості (`flags[]`, кожен з `code`, `severity`, `detail`): `LOW_VOLUME`, `SPIKE_DRIVEN` (зміна суттєво залежить від сплесків), `BASKET_SENSITIVE` (leave-one-out або без топ-3 змінює знак чи суттєво величину), `ANOMALY_MONTHS`, `BOT_SUSPECT`, `ARTICLE_MISSING`, `PROXY_USED`, `NEW_ARTICLE`, `PRE_2020_BOT_CLASS` (база до травня 2020, коли з'явився клас automated), `BOT_RECLASSIFICATION_2025` (вікно порівняння захоплює березень–серпень 2025), `PARTIAL_DATA`, `UNUSED_SERIES` (завантажена серія не входить у жоден кошик).

Довіра: для кожного головного твердження окремо `direction_confidence` і `magnitude_confidence` (`high` | `medium` | `low`) за явними правилами, із `reasons[]`. Приклад правила: напрям `high`, якщо всі варіанти стійкості мають той самий знак і інтервал індексу не містить 1; `medium`, якщо знак стабільний, але інтервал містить 1; `low` в інших випадках. Правила описати в коді й в appendix.

Вихід: `metrics.json` (повний) і в stdout короткий підсумок: головні числа по кошиках і мовах, довіра, прапорці, шлях до metrics.json.

## 9. Команда `report`

Вхід: `--metrics metrics.json --narrative narrative.json --out report.pdf [--report-lang uk|en]`.

narrative.json пише агент:
```json
{"title": "...", "answer": "Коротка відповідь (до ~300 символів)",
 "findings": ["Текст з плейсхолдерами на кшталт {target.uk.window.change_norm:pct}"],
 "recommendation": "...", "next_steps": ["..."], "caveats": ["..."]}
```
- Числа в тексті лише через плейсхолдери `{шлях.у.metrics:формат}`; формати `pct`, `int`, `x`, `ci`. Валідатор відхиляє будь-які інші цифри, крім чотиризначних років 19xx/20xx, і невідомі шляхи — з підказкою, який плейсхолдер використати.
- Сторінка 1 (рівно одна сторінка A4): заголовок, відповідь, бейдж довіри, графік (тип обирається за формою даних: одна мова — історія й вікно; кілька мов — індекси кошиків поруч), компактна таблиця ключових чисел, до 4 висновків, рекомендація, короткі застереження, рядок джерела з `data_as_of`.
- Додаток `appendix.md`: склад кошиків (з причинами виключень, якщо є), методика, усі прапорці, таблиця стійкості, джерела, як відтворити.
- Формат чисел за мовою звіту: для uk — десяткова кома, пробіл у тисячах, знак «−».
- Після верстки перевірити, що PDF має рівно 1 сторінку; якщо текст не вміщується — помилка з порадою, що скоротити, а не мовчазне обрізання.
- Графіки також окремими PNG.

## 10. Команда `doctor`

Перевіряє версію Python, імпорт залежностей, шрифт, запис у кеш, доступність трьох доменів (wikimedia.org, wikipedia.org, wikidata.org), наявність контакту для User-Agent. Вихід — JSON зі статусом кожної перевірки й підказками.

## 11. Тести і CI

- pytest; HTTP мокається на рівні сесії; фікстури — записані відповіді API (`tests/record_fixtures.py` записує їх, у CI не запускається).
- Юніт-тести метрик на синтетичних рядах з відомою відповіддю: геометричний індекс, bootstrap (детермінованість), leave-one-out, детектор сплесків, аномальні місяці, нормалізація, плейсхолдери й валідатор narrative, формат чисел uk.
- Регресійні тести resolve на кейсах з розділу 6.
- Офлайн e2e: `examples/` містить spec, narrative і знімок кешу для одного сценарію; ланцюжок `analyze → report` без мережі дає односторінковий PDF.
- GitHub Actions: ubuntu-latest, windows-latest, macos-latest × Python 3.10 і 3.12; `uv sync --locked`, pytest, офлайн e2e.

## 12. Поза межами контракту

Автоматичний підбір кошика тем (наприклад, із мета-списку «List of articles every Wikipedia should have» чи категорій) та інші кроки розвитку — у `docs/ROADMAP.md`; інтерфейс `resolve` має дозволяти їх додати без зламу контракту.
