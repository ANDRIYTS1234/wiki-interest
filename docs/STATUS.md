## Лишилось

### Обов'язкове за умовою завдання

1. **Прогони на дешевій моделі.** Умова вимагає перевірити повний сценарій на моделі рівня Haiku 4.5. Запустити `evals/run_agent.py` для сценаріїв A–E у двох режимах, оцінити `summary.json` за чеклістами `evals/scenarios.yaml`, звести таблицю «без навички / з навичкою» (pass серед critical і всіх, кроки, токени, час):
   ```bash
   export OPENROUTER_API_KEY=...
   uv run evals/run_agent.py --scenario B --mode skill    --model anthropic/claude-haiku-4.5
   uv run evals/run_agent.py --scenario B --mode baseline --model anthropic/claude-haiku-4.5
   ```
   Для C і E baseline треба знімати в той самий день, що й прогін з навичкою. Помилки, знайдені в прогонах, — виправити в коді або SKILL.md і повторити.
2. **Перевірка спрацювання навички** за `evals/triggers.yaml` (should_trigger / should_not_trigger) — `run_agent.py` цього поки не вміє; або дописати режим, або перевірити вручну в клієнті з підтримкою Agent Skills.
3. **Пояснення, як розвивати навичку далі.** Зараз — короткий розділ «Growing the skill» у README. Потрібен повний текст: більші кошики з Wikidata / мета-списків / категорій, паралельне завантаження зі спільним лімітом, помісячні ряди для довгої історії, ранжування багатьох мов, пошук підтем, що ростуть, цикл «помилка в прогоні → перевірка в evals → правило в коді».
4. **Пояснення, як перевірявся результат AI-інструментів.** Матеріал є (протоколи baseline, регресійні тести на записаних відповідях API, звірка analyze з доведенням baseline, ручний перегляд PDF), але `evals/verification-log.md` у репозиторії ще немає.

### Перевірити

5. **CI на Windows і macOS** — конфіг є, але зелені прогони ще не бачили; перше падіння, найімовірніше, буде через шляхи чи кодування.
6. **Приклад A наживо** — `fetch` + `analyze` + `report` на `examples/A-astronomy`, звірити з очікуваним результатом сценарію A (напрям «не зростає», аномальні січень–лютий 2024/2025, порівняння з контролем через індекси).
